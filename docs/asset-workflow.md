# 미니룸 에셋 제작 워크플로

미니룸에 들어갈 가구·소품 PNG를 만드는 방법. 지금은 전부 Canvas 도형이고,
이 문서대로 만든 PNG로 하나씩 갈아끼우면 된다.

---

## 0. 결론부터

**무료 CC0 3D 킷을 받아 → 파스텔로 리컬러 → 정해진 각도로 렌더 → PNG 저장.**

직접 2D로 그리는 것보다 빠르고, 2D 아이소메트릭 스프라이트 팩을 받는 것보다 낫다.

### 왜 2D 스프라이트 팩이 아니라 3D 킷인가

| | 2D 아이소메트릭 팩 | 3D 킷 리렌더 |
|---|---|---|
| 각도 | 원작자가 쓴 각도로 **고정**. 정확히 2:1이 아니면 격자에 안 맞아 전부 손보정 | 우리가 정한 각도로 렌더 → 타일에 픽셀 단위로 맞음 |
| 파스텔 리테마 | 아이템마다 픽셀 단위 리컬러 | 텍스처/머티리얼 한 번 고치면 전부 반영 |
| 방향 4장 | 각도별로 따로 그려야 함 | 모델 90°씩 돌려 렌더하면 끝 |

특히 **KayKit**은 모델 전체가 1024×1024 그라데이션 아틀라스 **한 장**을 공유해서,
그 텍스처만 파스텔로 바꾸면 전 아이템이 동시에 바뀐다. 우리 상황에 가장 잘 맞는다.

### CC0 킷 후보

전부 CC0 = 상업 이용·수정·재배포 자유, 출처 표기 불필요.

| 팩 | 규모 | 특징 |
|---|---|---|
| [KayKit Furniture Bits](https://kaylousberg.com/game-assets/furniture-bits) | 50+ | 단일 그라데이션 아틀라스 → **리테마 최적** |
| [Kenney Furniture Kit](https://kenney.nl/assets/furniture-kit) | 140 | 종류가 제일 많음 |
| [Quaternius](https://quaternius.com/) | 라이브러리 | 저폴리 전반 |

> **주의 1** — itch.io 팩은 라이선스가 제각각이다. 팩마다 확인하고, CC0 필터를 쓸 것.
> **주의 2** — 라이선스가 맞아도 **화풍은 안 맞는다.** 이 킷들은 채도 높은 저폴리라
> 시안의 부드러운 파스텔로 가려면 리컬러가 반드시 필요하다. 이건 건너뛸 수 없는 단계다.

### ⚠ Kenney 팩의 프리렌더 PNG는 그대로 못 쓴다 (실측 확인)

Kenney Furniture Kit에는 `Isometric/` 폴더에 **140종 × 4방향(NE/NW/SE/SW) = 561장**의
프리렌더 PNG가 들어있다. 방향 4장이 이미 있어서 솔깃하지만 —

**측정해보니 고도 45°, 타일 1.41 : 1 이라 우리 2:1 격자와 안 맞는다.**
(상자류 윗면 기울기 0.707, 그리고 원형 러그 바운딩박스 203×145 = 1.40 — 두 방법 일치)

세로로 눌러서 맞추면 바닥 발자국은 맞지만 **높이도 같이 눌려 원래의 58%로 납작해진다.**
가구가 눈에 띄게 낮아져서 쓰기 어렵다.

**대신 팩에 3D 모델이 같이 들어있다** (`Models/`, .obj/.fbx/.glb 각 140개).
이걸 블렌더에서 위 각도(고도 30°)로 다시 렌더하면 된다. 결국 3D 킷을 받는 이유가 이거다.

## 1. 카메라 (제일 중요)

**직교(Orthographic) 카메라**여야 한다. 원근(Perspective)이면 타일마다 크기가 달라져서
격자에 안 맞는다.

| 항목 | 값 |
|---|---|
| 투영 | Orthographic |
| Yaw (Z 회전) | **45°** |
| **고도각(elevation)** | **30°** |
| **Blender 카메라 회전** | **X = 60°, Y = 0, Z = 45°** |

### 왜 30°인가

직교 투영에서 지면 위 축의 화면 기울기는 `sin(고도각)`이고,
따라서 **타일 가로:세로 = 1 / sin(고도각)** 이다.

| 고도각 | 타일 비율 | |
|---|---|---|
| 26.565° | 2.236 : 1 | |
| **30°** | **2.000 : 1** | ← 우리 격자 (64×32) |
| 35.264° | 1.732 : 1 | true isometric |
| 45° | 1.414 : 1 | Kenney 프리렌더가 이것 |

> **정정** — 이 문서 초판에 "고도 26.565°"라고 적었던 것은 **틀렸다.**
> 26.565°(= atan 1/2)는 2:1 타일의 **화면상 모서리 각도**이지 카메라 고도각이 아니다.
> 두 값을 혼동하기 쉬우니 주의. 카메라 고도는 **30°**다.

확인법: 1×1×1 정육면체를 렌더해서 **윗면 마름모의 가로:세로가 정확히 2:1**이면 맞다.
받아온 스프라이트는 아래 명령으로 바로 잴 수 있다.

```
python tools/isoasset.py check 받은에셋/*.png
```

## 2. 크기 — 기본 단위와 4배 저작

코드는 **기본 단위**로만 아트를 다룬다. 기본 단위에서 타일 한 칸은 **64 × 32**다.

- 아트 크기를 기본 단위로 먼저 정한다. 예: 강아지집 = 72 × 80
- 저장은 **4배**로: 72×80 → **288 × 320 px**

4배인 이유: 실기기(1080px 폭)에서 방이 화면 전체를 쓰면 타일 폭이 180px,
즉 기본 단위 1 = 약 2.8px이다. 4배로 저작하면 화면에서 **항상 축소**되므로 늘 선명하다.
확대되는 일이 없어야 뭉개지지 않는다.

## 3. 기준점(anchor) — 어긋나면 물건이 공중에 뜬다

기준점은 **물건이 바닥에 닿는 점**이고, 그림자는 그 점을 **중심으로** 그려진다.
여기를 잘못 잡으면 물건이 떠 보인다 (실제로 겪은 버그다).

| 종류 | 기준점 | 예 |
|---|---|---|
| 바닥에 눕는 것 | **밑면 타원의 중심** | 방석, 밥그릇, 담요, 뼈다귀 |
| 바닥에 서는 것 | **바닥에 닿는 맨 아랫점** | 화분, 강아지집, 공 |

렌더할 때 바닥면 중심이 어디인지 기록해두고, 그 좌표를 기본 단위로 환산해 코드에 적는다.

## 4. 저장 위치 — `res/drawable-nodpi/`

**반드시 `nodpi`.** 그냥 `res/drawable/`에 넣으면 안드로이드가 mdpi 기준으로 보고
디코딩할 때 기기 density만큼(이 폰은 **2.625배**) 자동 확대한다.
우리는 코드에서 직접 크기를 맞추므로 이중 스케일이 되고 메모리도 2.6배 낭비된다.
`nodpi`는 "density로 건드리지 마라"는 뜻이라 파일 픽셀 그대로 들어온다.

배경은 **투명(알파)** 필수. 그림자를 구우려면 부드럽게, 아니면 빼고 코드에 맡긴다.

## 5. 스프라이트 시트 (움직이는 것)

- 프레임을 **격자로 배치, 행 우선**(왼쪽 위 → 오른쪽 → 다음 줄)
- 모든 프레임 크기가 같아야 한다
- 코드에 넘길 값: `frameWidth`, `frameHeight`, `columns`, `frameCount`, `fps`

예시 파일: `app/src/main/res/drawable-nodpi/lantern_sheet.png`
(프레임 144×192, 4열, 4프레임, 4fps)

**힉스필드 강아지**는 영상으로 나오므로 → 프레임 추출 → 배경 제거(알파) → 격자로 합치기
순서가 필요하다. 그리고 **강아지는 아이소메트릭이 아니어도 된다.**
쿠키런 킹덤도 배경만 아이소메트릭이고 캐릭터는 정면/3-4 뷰 빌보드다.
작은 화면에서 진짜 아이소메트릭 캐릭터는 얼굴이 안 읽힌다.

## 6. 코드에 꽂기

`app/src/main/java/com/daengs/app/miniroom/art/ItemCatalog.kt`의 해당 줄만 바꾼다.

```kotlin
// 지금 (도형)
"plant" to ItemArtSpec.Shapes(
    ArtBox(size = Size(44f, 96f), anchor = Offset(22f, 88f)),
) { drawPlant() },

// PNG 로 교체
"plant" to ItemArtSpec.Res(
    ArtBox(size = Size(44f, 96f), anchor = Offset(22f, 88f)),
    resId = R.drawable.plant_01,
),
```

`ArtBox`(크기·기준점·차지하는 칸)만 그대로면 **정렬·터치판정·스냅·점유 계산은
한 줄도 안 바뀐다.** 도형 그리는 함수는 그냥 안 불리게 된다.

스프라이트 시트는 `ItemArtSpec.Sheet`에 `resId`와 프레임 값들을 넣는다.

### 리컬러 (파스텔로 바꾸기)

받은 에셋을 우리 톤으로 바꾸는 건 스크립트 한 번이면 된다.

```
python tools/isoasset.py pastel 받은에셋/*.png -o app/src/main/res/drawable-nodpi
```

채도를 낮추고 명도를 올려서 파스텔로 만든다. 세기 조절:
`--sat 0.42`(낮을수록 연함) `--lift 0.16`(명도) `--warm 0.02`(따뜻한 쪽으로)

색상(hue)은 유지하므로 나무·천·금속 같은 재질 구분은 살아있다.

### 보간 방식

`filterQuality`로 아이템마다 고를 수 있다.

- **부드러운 파스텔 아트** → `FilterQuality.Medium` (기본값). 축소될 때 매끄럽다.
- **픽셀 아트** → `FilterQuality.None`. 최근접 이웃이라 도트가 살아있다.

섞어 써도 된다.
